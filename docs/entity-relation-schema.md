# Entity·Relation 검색 스키마

Issue #52 구현 브랜치 기준. 이 문서는 코드에 반영된 형식과 남은 제한을 기록한다. 문서 참조 그래프 PR #51을 선행 변경으로 둔다.

## Entity

Entity 유형은 `PROJECT`, `PROCESS`, `SYSTEM_SERVICE`, `ORG_UNIT`, `POLICY`, `CONCEPT`다. 사람은 제외한다. 이름 정규화는 검색 표기를 비교할 때 쓰며, Entity ID는 문서 이름 대신 namespace, 유형, 정규화 정식 이름으로 결정한다. 현재 namespace는 단일 서비스 값 `docs199`다. 여러 조직의 문서를 하나의 DB에서 분리해 색인할 때는 이를 백엔드의 실제 tenant/collection 식별자에 연결해야 한다.

`MENTIONS`는 실제 청크 표면형, 표면형 위치, 이를 포함한 원문 인용 위치를 보존한다. `ENTITY_EXTRACTION_ENABLED=true`일 때만 각 문서의 각 청크를 설정된 LLM에 보내 후보를 추출한다. 기본은 꺼져 있으며, 켜기 전에 외부 전송 범위(`docs199-Server#14`)를 정해야 한다. 인용과 표면형이 원문에 정확히 존재하고 위치가 청크 범위에 포함될 때만 저장한다. 짧은 인용에 이름이 여러 번 나오면 각 이름 위치를 별도 mention으로 저장한다.

## Relation

`REFERENCES`는 문서 참조 그래프에서 원문 표기와 명시적 문서 제목이 유일하게 확인될 때 만드는 문서 간 연결이다. 업무 관계를 뜻하지 않는다. 업무 관계는 해당 문서 버전 안의 `RelationAssertion`으로 보존한다.

| predicate | 주어 → 목적어 |
|---|---|
| `RESPONSIBLE_FOR` | 조직 단위 → 프로젝트·업무·시스템·정책 |
| `USES` | 프로젝트·업무 → 시스템·서비스 |
| `GOVERNED_BY` | 프로젝트·업무 → 정책 |

추출 후보는 근거 인용이 청크 원문과 일치하고 양쪽 Entity mention이 그 청크에 존재할 때 저장한다. 현재 검색의 관계 의도 판별은 ‘담당/관리/누가/소유’, ‘사용/이용/어디서’, ‘규정/적용/따르’ 문자열 규칙이다. 감지된 predicate와 질문 Entity가 같은 assertion의 주어·목적어에 있을 때 근거 청크를 후보로 올린다. 관계 기반 답변도 원문 청크를 다시 회수해 생성한다.

부정, 예정, 조건부 assertion은 저장 스키마에서 표현하지만, 현재는 확정된 `AFFIRMED`·`ACTUAL` 관계만 검색용 관계로 적재한다. 조건부 관계 질의와 예외 처리는 별도 평가 후 추가해야 한다.

추출은 청크마다 최대 4,096토큰을 출력한다. 응답이 잘리거나 형식이 틀린 청크는 건너뛰고 문서 단위 경고 `Entity extraction incomplete`를 남긴다. 이때 문서의 그래프는 남은 결과로 교체되므로 관계가 줄어들 수 있다.

## 저장 흐름과 경계

1. 색인기는 문서를 청크로 나누고 기존 벡터 저장소에 청크를 기록한다.
2. Neo4j 문서·청크 노드를 갱신한 다음 청크별 Entity 및 관계 후보를 추출한다.
3. 근거 인용·이름 위치·문서/버전 소속을 검증하고 mention·assertion 식별자를 결정적으로 만든다.
4. 문서 버전별 mention·assertion을 Neo4j 트랜잭션으로 교체한다.
5. 질문에서는 문서 제목 seed와 Entity mention seed, 일치하는 관계 주장 근거를 합친다. 본문은 기존 벡터 저장소의 접근 가능 검색으로 가져온다.

그래프에는 문서 전체를 저장하지 않지만, 근거 인용(`evidence_quote`, `condition_quote`)은 저장한다. Neo4j에는 권한이 없으므로 접근 권한이 없는 저장소에 문서 일부가 남는다는 점을 전제로 Neo4j 접근을 제한해야 한다. 로그에 문서 본문이나 인용을 쓰지 않는다. 현재 그래프에는 권한 정보를 저장하지 않으며, 문서 내용은 기존 접근 가능 청크 함수에서 최종 검증한다.

## 이번 구현의 범위와 남은 검증

- `EntityAlias`와 사용자 관리 alias 연결은 아직 저장·검색 경로에 연결되지 않았다. 다른 이름·약칭을 연결하려면 등록 자료와 모호성 해소 규칙이 필요하다.
- 명시적 `《문서명》`, `[[문서명]]` 참조의 현재 생성 경로는 유지한다. 자유 문장 문서명 후보의 LLM 추출과 미해결 후보 검토 대기열은 미구현이다.
- 현재 Entity ID는 서비스 단일 namespace를 사용한다. 멀티테넌트가 필요할 때는 임의 문자열로 범위를 나누지 말고 Spring이 확정한 namespace를 받아야 한다.
- 추출 코드 및 relation Cypher에 대해 자동 회귀 테스트와 실제 격리 Neo4j 실행을 추가해야 한다. 실제 질문 평가 전에는 검색 품질 향상을 주장하지 않는다.
