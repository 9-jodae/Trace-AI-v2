# 문서 추출·분류·검증·저장 설계

기준일: 2026-11-05 / 이슈 #27 / AI 내부 규격 1.0

이 문서는 `app/ingestion`의 실제 구현을 설명한다. Spring과 합의된 API 계약을 대체하지 않는다. 원본 파일 파싱·OCR과 백엔드 콜백은 후속 범위다.

## 1. 실행 진입점

- HTTP: `POST /api/v1/ingestion/documents`에 추출된 원문 JSON 전달.
- CLI: `python -m app.ingestion <입력.json>`.
- Python: `prepare_document(DocumentSubmission)`으로 정규화하고 `store_document(NormalizedDocument)`로 저장.
- `--normalize-only`: DB 없이 추출·분류·검증만 수행. LLM 설정이 유효하면 모델 호출 비용이 발생할 수 있다.
- `--output output/normalized.json`: 정규화 결과를 파일로 저장. 원문과 근거가 포함되므로 커밋하지 않는다. `output/`은 gitignore 대상이다.

HTTP는 운영에서 `X-Internal-Secret` 검증을 사용한다. `APP_ENV=local`에서만 기존 개발용 인증 생략 정책을 따른다. 신뢰할 수 있는 서버 호출자가 입력 메타데이터와 권한을 제공해야 한다.

## 2. 공통 입력 필드

JSON은 camelCase다. Python에서는 snake_case 이름으로 접근한다. 정의하지 않은 필드는 거부한다. 정확한 규격은 [생성된 입력 Schema](schemas/document-submission.schema.json)에 있다.

| 필드 | 필수 | 처리 |
|---|---|---|
| documentId | 예 | 1~300자 식별 문자열. 외부에서 부여한 문서 ID 유지 |
| versionId | 예 | 1~300자 버전 식별 문자열. 호출자는 전역적으로 유일한 버전 ID를 사용 |
| versionNumber | 예 | 1 이상 정수. true/false·문자열을 정수로 대체하지 않음 |
| title | 예 | 1~300자. 입력 제목 유지, 앞뒤 공백 제거 |
| text | 예 | 공백뿐인 원문 거부. 최대 200,000자. 문자 위치 보존을 위해 내용·공백을 변경하지 않음 |
| status | 예 | 유효 / 폐기. 분류·적재 작업 상태와 별개 |
| allowedGroupIds | 예 | 1개 이상, 최대 1,000개. 빈 그룹 거부, 중복 제거 |
| sourceUri | 아니오 | 원본 위치. 실제 파일 다운로드에 사용하지 않음 |
| author | 아니오 | 원본 메타데이터. 없으면 null |
| authoredAt | 아니오 | 원본 작성일. 시행일·수집일과 자동 치환하지 않음 |
| sourceModifiedAt | 아니오 | 시간대가 있는 원본 수정 시각. 없으면 null |
| department | 아니오 | 신뢰 메타데이터. 본문 언급만으로 추정하지 않음 |
| documentType | 아니오 | 원본의 확정 분류. 있으면 LLM보다 우선 |

제목·본문은 현재 파서가 만들어주는 값이 아니라 입력 규격으로 받는다. API 메타데이터 매핑과 원문 추출 책임은 향후 AI 파서 계층이 담당한다. 문서 작성자·수정일을 업로더·업로드 시각으로 자동 대체하지 않는다.

## 3. 속성 추출 책임

| 값 | 현재 생성 방식 |
|---|---|
| 문서·버전 ID, 버전 번호, 제목, 작성자, 날짜, 부서, 권한 | 신뢰 입력에서 매핑 |
| contentHash | 원문 UTF-8 바이트의 SHA-256 |
| Chunk ID | 문서 ID·버전 ID·원문 해시·청킹 설정·순번으로 UUID5 계산 |
| 문서 유형 | 원본 확정값 우선. 없으면 LLM 결과와 인용 검증 |
| 주제/키워드 | LLM 후보와 인용 검증 후 대소문자 기준 중복 제거 |
| 명시적 문서 참조 | LLM이 대상 제목·인용을 추출. DB에서 실제 대상 ID를 결정 |
| 인용 문자 위치 | 모델에게 숫자를 추정시키지 않고 원문 문자열 검색으로 계산 |
| fieldSources | metadata / system / llm / unresolved 기록 |

## 4. LLM 추출

답변 생성과 동일한 `LLM_MODEL`, `LLM_API_KEY` 또는 AWS 자격 증명, `LLM_FALLBACK_MODEL`을 재사용한다. 새 외부 모델을 임의로 고정하지 않는다.

LLM에는 제목과 본문만 보낸다. 문서 데이터 안의 지시를 따르지 않도록 시스템 메시지에서 구분하고 JSON으로 감싼다. 모델 출력은 아래 항목만 허용하며, 추가 필드는 Schema 오류다.

- documentType: `{value, quote}` 또는 null.
- topics: `{value, quote}` 목록, 최대 20개.
- references: `{targetTitle, quote}` 목록, 최대 30개.

유형은 HANDOVER / APPROVAL / REPORT / PRESENTATION / ETC다. ETC는 분류된 기타이고 판단 불가와 구분한다. 권한·작성자·날짜·대상 문서 ID는 모델 출력에 허용하지 않는다.

원문이 `EXTRACTION_MAX_TEXT_CHARS`(기본 24,000자)를 넘으면 일부만 잘라서 전체를 분류하지 않는다. LLM 호출을 건너뛰고 EXTRACTION_LIMIT 검토 사유를 남긴다. 원문 적재 상한 200,000자와 LLM 입력 상한은 별개다. 모델 응답도 64,000자를 초과하면 한도 초과로 처리한다.

## 5. 근거·중복·관계 검증

- 인용은 원문에 동일한 문자열로 존재해야 한다. 원문에 없는 분류·주제·참조 인용은 채택하지 않는다.
- `charStart`는 0부터 시작하고 `charEnd`는 끝을 포함하지 않는다. `text[charStart:charEnd]`가 인용과 같아야 한다.
- 인용이 반복되면 현재는 첫 일치 위치를 사용한다. 페이지·블록별 정밀 추적은 파서 이후 확장한다.
- 주제·참조 대상 제목을 casefold 기준으로 중복 제거한다.
- 참조 대상 제목은 인용 구간에도 실제로 등장해야 한다.
- 현재 문서와 같은 제목의 참조는 SELF_REFERENCE로 검토 대기 처리한다.
- Neo4j에서 제목이 일치하고 유효·READY이며 접근 그룹이 겹치는 대상 문서를 조회한다.
- 대상이 없거나 여러 개면 검토 대기이며, 임의로 대상을 고르지 않는다.
- 대상이 하나면 문서 ID와 버전 ID를 연결하고 VALIDATED 상태로 저장한다.
- 실제 관계 저장 트랜잭션에서도 대상의 버전·권한·유효·READY 상태를 다시 확인한다.

VALIDATED는 현재 구현의 구조·원문·대상 검증을 통과했다는 뜻이다. 사람의 의미 검토나 분류의 절대적 정확성을 뜻하지 않는다. 명시적 참조 여부에 대한 LLM 오판은 별도의 품질 평가 대상이다.

## 6. 분류·검토 상태

| 상황 | 결과 |
|---|---|
| 원본 documentType 있음 | 원본 분류 유지, CLASSIFIED / SOURCE_METADATA |
| 모델 유형의 인용이 원문에 있음 | 모델 분류, CLASSIFIED / GROUNDED_MODEL_CLASSIFICATION |
| 유형 판단 불가 | null, REVIEW_REQUIRED / UNCLASSIFIED |
| 분류 인용이 원문에 없음 | null, REVIEW_REQUIRED / INVALID_CLASSIFICATION_EVIDENCE |
| LLM 응답 구조 오류 | 원본 분류가 없으면 REVIEW_REQUIRED / INVALID_EXTRACTION_SCHEMA |
| LLM 호출 실패 | 원본 분류가 없으면 REVIEW_REQUIRED / EXTRACTION_UNAVAILABLE |
| 추출 입력·출력 한도 초과 | 원본 분류가 없으면 REVIEW_REQUIRED / EXTRACTION_LIMIT |

PENDING은 내부 Enum에 예약되어 있지만 동기 정규화 결과는 CLASSIFIED 또는 REVIEW_REQUIRED다. `classificationStatus`는 문서 유형의 상태이고, 주제·관계의 검토 사유는 `reviewReasons`에 따로 남는다. 예를 들어 문서 유형이 확정되어도 참조 대상은 검토 대기일 수 있다.

관계 사유는 TARGET_UNRESOLVED / AMBIGUOUS_TARGET / SELF_REFERENCE다. 원문 검증에 실패한 후보는 INVALID_TOPIC_EVIDENCE / INVALID_REFERENCE_EVIDENCE를 남기고 결과에서 제외한다.

분류가 불확실해도 유효한 원문·권한이 있으면 적재한다. 잘못된 입력·DB 실패·버전 충돌은 적재 실패다. 분류 상태를 백엔드 작업의 DONE/FAILED와 혼동하지 않는다. 현재 백엔드로 작업 완료 콜백을 전송하지 않는다.

## 7. 정규화 데이터 및 DB 매핑

정규화 결과는 입력 필드에 schemaVersion, contentHash, classificationStatus, classificationReason, classificationEvidence, topics, references, reviewReasons, fieldSources를 추가한다. [정규화 Schema](schemas/normalized-document.schema.json)를 참고한다.

Neo4j는 Document 노드에 원문·메타데이터·최종 유형·검토 사유를 저장한다. 중첩된 근거·주제·참조·필드 출처는 `*_json` 문자열 속성으로 보관한다. 주제명 목록은 `topics` 속성에도 저장한다. 확정된 문서 참조만 REFERENCES 엣지로 만들고 양쪽 버전·인용·문자 위치를 기록한다.

Qdrant에는 Chunk와 임베딩, 문서·버전, 원문 위치, 상태·권한 그룹, 분류 상태·유형·사유, 주제명, 작성자·작성일·수정일·부서, 원문 해시·Schema 버전을 저장한다. 근거 상세는 정규화 데이터와 Neo4j에서 추적한다. 전체 원문을 각 Chunk에 반복해서 넣지 않는다.

## 8. 저장 공개·재시도

1. 후보를 검증하고 실제 대상 문서를 조회한다.
2. 원문을 800자/100자 중첩 설정으로 청킹하고 임베딩한다.
3. Qdrant에 STAGING으로 저장한다. 검색에서는 숨긴다.
4. Neo4j의 한 트랜잭션에서 버전을 확인하고 Document·REFERENCES를 갱신한다. 문서는 STAGING이다.
5. Qdrant의 해당 버전을 READY로 공개한다.
6. Neo4j에서 ID·버전·본문 해시가 맞으면 READY로 전환한다.
7. 직전 버전이 있으면 그 문서·버전의 벡터만 정리한다.

현재 검색은 최종적으로 Neo4j의 버전·본문 해시·권한·상태까지 확인한다. 부분 저장·과거 버전은 필터링된다. 분산 원자적 롤백은 없으므로 단계 4 이후 실패하면 이전 버전도 검색에서 일시 제외될 수 있다. 실패를 성공으로 보고하지 않고 같은 입력의 재시도가 필요하다. 자동 작업 큐·영속 멱등 처리·오래된 STAGING 정리는 후속이다.

원문 해시나 버전이 충돌하면 HTTP 409다. 원본 내용이 바뀌면 새 versionId와 증가한 versionNumber를 전달해야 한다. Chunk ID에는 본문 해시도 포함되어 기존 근거 ID가 다른 본문을 가리키지 않는다.

## 9. 내부 API 결과와 오류

성공 응답에는 documentId, versionId, chunkCount, documentType, classificationStatus, reviewReasons, referenceCount가 있다. 원문은 응답 요약에 넣지 않는다.

| HTTP | 의미 |
|---|---|
| 200 | 두 저장소 공개까지 완료. 분류 검토 대기여도 성공할 수 있음 |
| 401 | 운영 내부 인증 실패 |
| 422 | 입력 Schema 오류 |
| 409 | 버전·원문·참조 대상 변경 충돌 |
| 503 | 저장소 사용 불가, 적재 실패, 요청 시간 초과 |

HTTP 적재 제한 시간은 INGESTION_TIMEOUT_SECONDS(기본 180초)다. CLI 전체 시간 제한과 영속 비동기 작업은 아직 없다. 예외의 원문이나 문서 본문을 로그·오류 응답으로 내보내지 않는다.

## 10. 예시 및 실행

[data/ingestion_document.example.json](../data/ingestion_document.example.json)은 가상 문서를 사용하는 입력 예시다.

```bash
python -m app.ingestion data/ingestion_document.example.json --normalize-only --output output/normalized.json
python -m app.ingestion data/ingestion_document.example.json
```

첫 명령은 정규화만 수행하며, 두 번째는 Qdrant와 Neo4j 저장까지 수행한다. 실제 저장에는 VECTOR_STORE=qdrant, Qdrant·Neo4j 접속 정보와 임베딩 모델 설정이 필요하다. LLM만 실패하면 검토 대기로 진행하지만, 임베딩·DB 설정이 없으면 저장은 실패한다.

원본 PDF/DOCX·스캔 문서·Notion·Drive를 직접 전달하는 기능은 이 예시에 포함되지 않는다. 입력 파서가 생기면 동일한 DocumentSubmission 규격으로 연결한다.
